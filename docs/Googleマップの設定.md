# Google マップの設定

Tri-Tri の地図・場所の候補・移動時間は、Google マップの API を使う。
**API キーを設定しなければ、仮の仕組みで動く**(決まった 21 か所から探す場所の候補・位置関係だけの簡略図・直線距離からの移動時間の目安)。自動テストと CI はいつもこちらで動く。

## 使う API

| 画面で使うところ | API | 取るもの |
|---|---|---|
| 地図とピン | Maps JavaScript API | 地図の表示 |
| 場所の入力中の候補・場所の座標 | Places API (New) | 候補(セッショントークンでまとめる)と、ID から引いた座標(`location`)だけ |
| 区間ごとの移動時間と経路の線 | Routes API | 所要時間(`durationMillis`)・線(`path`)・注意(`warnings`)だけ |

利用回数を抑えるための作り:
- 候補を問い合わせるのは、2 文字以上入れて入力が 0.3 秒止まったときだけ
- **候補の問い合わせは 1 回の検索で 2 回分**(ふつうの検索 + 駅・バス停などに絞った検索)。Google の候補は 1 回 5 件までで増やせないため。1 日の上限が 300 回なら、入力が止まるのは 150 回分で届く
- 近くを優先するための座標は、基準の 1 か所だけを取る(取得済みなら問い合わせない)
- 20 件出せる Text Search は使わない(無料が月 5,000 回、超えると 1,000 回あたり 32 ドル。2026-11-22 時点)
- 区間の移動時間は、地図で選んでいる日の分だけ問い合わせる。同じ区間・同じ手段の結果は、画面を開いている間は覚えておき、もう一度は問い合わせない
- 公共交通は経由地を指定できないため、区間ごとに 1 回ずつ問い合わせる
- 問い合わせに失敗しても、同じものは 60 秒たつまで問い合わせ直さない

回数の目安: 場所が 4 か所ある日の画面を 1 回開く(または再読み込みする)と、**座標 4 回・経路 3 回**。移動手段を替えると、経路がさらに 3 回。1 日 300 回の上限なら、その画面を 75 回ほど開くと座標の上限に届く。公開しおりを多くの人に見せる前に見直す。

## 保存してよいもの
[Places API の方針](https://developers.google.com/maps/documentation/places/web-service/policies)に合わせる。

| もの | 扱い |
|---|---|
| 場所の ID | 保存する(期限なし。ただし 12 か月より古い ID は取り直しが勧められている。変わったり無効になったりすることがある) |
| 利用者が入力した表示名 | 保存する |
| 座標 | 保存しない(方針では一時的に 30 日まで。このアプリはメモリにだけ持つ) |
| Google の名前・住所・候補、経路・移動時間 | 保存しない |

Google から取ったものを地図の外に出すときは「Google Maps」と表示する(訳さない・大文字小文字を変えない)。

## 日本の公共交通
Routes API は日本の公共交通の経路を返さない([FAQ](https://developers.google.com/maps/faq)。2026-11-22 に京都・東京で 0 件、ロンドン・ソウルでは取得できることを確認)。設定の誤りではない。画面には「Google マップで調べる」リンクを出す。

## キーの作り方
1. [Google Cloud コンソール](https://console.cloud.google.com/) でプロジェクトを作り、請求先アカウントをつなぐ
2. 「API とサービス」→「ライブラリ」で、次の 3 つを有効にする
   - Maps JavaScript API
   - Places API (New)
   - Routes API

   途中で「API キーの保護」の画面が出たら「HTTP リファラー(ウェブサイト)」を選ぶ。このときキーは自動で作られているので、次の 3 では新しく作らずにそのキーを使い、4 の制限を確かめる
3. 「API とサービス」→「認証情報」→「認証情報を作成」→「API キー」
4. 作ったキーに、**必ず制限をかける**。このキーは画面の中に埋め込まれるので、誰でも見られる
   - **アプリケーションの制限**: 「ウェブサイト」を選び、次を入れる
     - `http://localhost:3000/*`(手元の開発用)
     - 公開したら、その URL(例: `https://xxxx.cloudfront.net/*`)
   - **API の制限**: 「キーを制限」を選び、上の 3 つの API だけにする

## 1 日の上限と予算の通知
各 API には毎月の無料の利用回数がある。回数は API ごとに違い、変わることもあるので、[料金のページ](https://mapsplatform.google.com/pricing/) で確かめる。
無料の範囲に収めるため、次のように上限を設定する。

- 「API とサービス」→ 各 API →「割り当てとシステム上限」で、**1 日あたりのリクエスト数**の上限を決める。月の無料回数 ÷ 31 より少なくする。例: 月 10,000 回なら 1 日 300 回
- 「お支払い」→「予算とアラート」で、少ない金額(例: 100 円)の予算を作り、超えそうになったらメールで知らせるようにする

## 地図のスタイルの ID(Map ID)
番号つきのピン(Advanced Marker)には Map ID が要る。
- 設定しなければ、Google の試用の ID(`DEMO_MAP_ID`)を使う。手元で試すにはこれで足りる
- 公開するときは、コンソールの「Google Maps Platform」→「マップ管理」で JavaScript 用の Map ID を作って設定する。ダークモードの暗い地図は、その ID のスタイルに従う

## 手元での設定
1. `web/.env.example` を `web/.env` にコピーする(`web/.env` は git に入れない)
2. キーを書く(キーの名前ではなく、「鍵を表示」で出る `AIza` で始まる文字列。`=` の行だけに貼る)
   ```
   NUXT_PUBLIC_GOOGLE_MAPS_API_KEY=作ったキー
   NUXT_PUBLIC_GOOGLE_MAPS_MAP_ID=
   ```
3. 画面の開発用サーバー(`pnpm dev:web`)を起動し直す

ブラウザ操作テスト(`pnpm test:e2e`)は、`web/.env` にキーがあっても仮の仕組みで動く(テストの設定でキーを空にしている)。

## うまく動かないとき
- 地図のところに「地図を読み込めませんでした」と出る、または地図が灰色になる: ブラウザの開発者ツールのコンソールで、Google のエラーを見る
  - `RefererNotAllowedMapError`: キーのウェブサイトの制限に、今の URL が入っていない
  - `ApiNotActivatedMapError`: その API が有効になっていない
- 移動時間が「時間はここでは出せません」になる: その区間・その手段の経路が Google に無い(日本の公共交通はいつもこうなる)
- 「時間を取得できませんでした」「地図に出せなかった場所」になる: 通信・キーの制限・1 日の上限のどれか。コンソールのエラーと、Google Cloud の割り当ての使用量を見る
