# トリトリ(TriTri)データ設計(DynamoDB)

> DynamoDB は「どの画面で、何を、どう読むか」を先に決めてからキーを決める。下の「アクセスパターン」がすべて、Scan を使わずに Query / GetItem / TransactWrite で行えることを確かめた。

## テーブル
### Main テーブル(1 テーブルに全種類を入れる)
- キー: `PK`(パーティションキー)、`SK`(ソートキー)
- GSI1: `GSI1PK`、`GSI1SK`(「自分の旅の一覧」用)

| 種類 | PK | SK | GSI1PK / GSI1SK | 主な項目 |
|---|---|---|---|---|
| 会員 | `USER#<userId>` | `PROFILE` | — | displayName、deletedAt |
| 旅 | `TRIP#<tripId>` | `META` | — | title、startDate、endDate、destination、ownerId、memberCount、inviteToken、publicToken、version |
| メンバー | `TRIP#<tripId>` | `MEMBER#<userId>` | `USER#<userId>` / `TRIP#<joinedAt>#<tripId>` | role(owner/member)、displayName、joinedAt |
| 予定 | `TRIP#<tripId>` | `ITEM#<itemId>` | — | day(何日目)、order、time、title、place{name, placeId, lat, lng}、memo、version、updatedBy |
| 候補 | `TRIP#<tripId>` | `IDEA#<ideaId>` | — | place、note、voteCount、createdBy、adoptedItemId |
| 投票 | `TRIP#<tripId>` | `VOTE#<ideaId>#<userId>` | — | votedAt |
| 支出 | `TRIP#<tripId>` | `EXP#<expenseId>` | — | title、amount(円・整数)、paidBy、splitWith[] |
| コメント | `TRIP#<tripId>` | `CMT#<itemId>#<commentId>` | — | body、userId、createdAt |
| 招待リンク | `INVITE#<token>` | `INVITE` | — | tripId |
| 公開リンク | `PUBLIC#<token>` | `PUBLIC` | — | tripId |

- ID は ULID(時刻順に並ぶ)を使う。
- 予定の並び順 `order` は、間に挟める文字列(fractional index)にする。並べ替えでは動かした 1 件だけを書き換える。
- 予定を別の日へ動かしても、キーは変えない(`day` を書き換えるだけ)。キーを変えると「削除+作成」になり、楽観ロックが効かなくなるため。
- メンバーの表示名は `MEMBER` にも写しておく(旅の画面を 1 回の Query で出すため)。表示名の変更時に、GSI1 で自分の旅を引いて書き換える。

### Connections テーブル(WebSocket の接続)
| PK | SK | 主な項目 |
|---|---|---|
| `TRIP#<tripId>` | `CONN#<connectionId>` | userId、displayName、ttl |
| `CONN#<connectionId>` | `CONN` | tripId(切断時に旅を引くため)、ttl |

- `ttl` で 2 時間後に自動削除(切断の通知が来なかった場合の掃除)。

## アクセスパターン
| # | 画面 | 操作 | やり方 |
|---|---|---|---|
| A1 | S05 | 自分の旅の一覧 | GSI1 を `GSI1PK = USER#<userId>` で Query → 各旅の META を BatchGet |
| A2 | S06 | 旅の作成 | TransactWrite: META + オーナーの MEMBER + INVITE |
| A3 | S07 | 旅の画面を開く | `PK = TRIP#<tripId>` で Query 1 回(META・メンバー・予定・候補・投票・支出・コメントをまとめて取る) |
| A4 | S07 | メンバーか確かめる | GetItem `TRIP#<tripId>` / `MEMBER#<userId>`(すべての API の最初に行う) |
| A5 | S08 | 招待で参加 | GetItem `INVITE#<token>` → TransactWrite: MEMBER を作る(`attribute_not_exists`)+ META の `memberCount` を +1(条件 `memberCount < 50`) |
| A6 | S07 | 予定の追加 | PutItem(条件 `attribute_not_exists`)、version = 1 |
| A7 | S07 | 予定の更新・並べ替え | UpdateItem(条件 `version = 送られてきた version`)、version + 1。条件に合わなければ 409 と今の内容を返す |
| A8 | S07 | 予定の削除 | TransactWrite: ITEM の削除(条件 `version` 一致)+ その予定のコメント(`CMT#<itemId>#` で Query して削除) |
| A9 | S07 | 投票 | TransactWrite: VOTE を作る(`attribute_not_exists`)+ IDEA の `voteCount` を +1 |
| A10 | S07 | 投票の取り消し | TransactWrite: VOTE を消す(`attribute_exists`)+ IDEA の `voteCount` を −1 |
| A11 | S07 | 候補の採用 | TransactWrite: ITEM を作る + IDEA に `adoptedItemId` を入れる(条件 `attribute_not_exists(adoptedItemId)`) |
| A12 | S07 | 支出・コメントの追加・削除 | PutItem / DeleteItem(削除は本人か、支出はメンバーなら誰でも) |
| A13 | S10 | 公開しおり | GetItem `PUBLIC#<token>` → A3 と同じ Query。META・メンバー・予定だけを返す |
| A14 | S09 | オーナーの引き継ぎ | TransactWrite: 自分と相手の MEMBER の role を入れ替え + META の ownerId(条件 `ownerId = 自分`) |
| A15 | S09 | メンバーが抜ける・外される | TransactWrite: MEMBER の削除 + `memberCount` を −1。オーナーは抜けられない(先に引き継ぐ) |
| A16 | S09 | 招待・公開リンクの発行し直し・停止 | TransactWrite: 古い INVITE/PUBLIC を消す + 新しいものを作る + META を書き換える |
| A17 | S11 | 退会 | オーナーの旅は先に自動で引き継ぐ(最も早く参加したメンバー)。1 人だけの旅は残す。PROFILE に `deletedAt`、各 MEMBER の displayName を「退会した会員」に。Cognito のユーザーを削除 |
| A18 | — | 変更を全員に届ける | Connections を `PK = TRIP#<tripId>` で Query → 各接続に送る。送れない接続(410)は消す |

## テストで確かめる条件(TDD のテスト一覧)
API の結合テスト(DynamoDB Local)で、先にこれらを失敗するテストとして書いてから実装する。

### 権限
- [ ] ログインしていないと、公開しおり以外の API はすべて 401
- [ ] メンバーでない旅の API は、旅が無いときと同じ 404(旅があることを知られない)
- [ ] オーナー専用の操作をメンバーが行うと 403
- [ ] 公開しおりの API は、割り勘とコメントを返さない。止めたリンクは 404

### 参加と上限
- [ ] 招待リンクで参加できる。2 回参加しても 1 人として数える
- [ ] 50 人目までは参加でき、51 人目は参加できない
- [ ] 残り 1 枠に 2 人が同時に参加しても、50 人を超えない
- [ ] 発行し直した後の古い招待リンクでは参加できない

### 同時編集
- [ ] 正しい version での更新は成功し、version が 1 増える
- [ ] 古い version での更新は 409 で、今の内容が返る
- [ ] 2 人が同じ version から同時に更新すると、片方だけ成功する
- [ ] 並べ替えで、動かした予定以外は書き換えない

### 投票・採用
- [ ] 同じ候補に 2 回投票しても 1 票。同時に 2 回押しても 1 票
- [ ] 取り消すと票数が減る。投票していないのに取り消しても票数は減らない
- [ ] 同じ候補を 2 人が同時に採用しても、予定は 1 件だけできる

### 割り勘(画面とも共通の計算。純粋な関数として単体テスト)
- [x] 全員が同じ額を払ったら、精算は 0 件
- [x] 割り切れない額の端数は、払った人の負担になる
- [x] 送金の回数が「人数 − 1」回以下になる
- [ ] 抜けたメンバーの支出も精算に含まれる(API の結合テストで確かめる)

### オーナーと退会
- [ ] オーナーは引き継ぐ前に抜けられない
- [ ] 引き継ぐと、前のオーナーはメンバーになる
- [ ] オーナーが退会すると、最も早く参加したメンバーがオーナーになる
- [ ] 1 人だけの旅は、退会しても残り、公開リンクで見られる。名前は「退会した会員」

### リアルタイム
- [ ] 予定を変えると、同じ旅に接続している全員に届き、別の旅の接続には届かない
- [ ] 切れている接続に送ろうとしたら、その接続を消す
