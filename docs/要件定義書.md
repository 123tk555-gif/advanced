# トリトリ(TriTri)要件定義書

> 状態: 確認事項はすべて決定済み(最後の「決定事項のまとめ」を参照)。

## 概要
**トリトリ(TriTri)**は、友人や家族と、**1つの旅のしおりを全員で同時に作る** Web アプリ。旅程の編集・行きたい場所の投票・割り勘・コメントを、メンバー同士がリアルタイムにやり取りする。予定の場所は Google マップで地図と経路を表示する。
最終的にインターネット上へ公開する。

## 背景・方針
- 講義の課題「複数のユーザーが情報を双方向にやり取りし、共有する Web アプリ」として作る。
- 前回の SNS アプリ(Leafline)から、**TypeScript と AWS 以外の技術をすべて入れ替える**(課題の指示)。

| 層 | 前回(Leafline) | 今回 |
|---|---|---|
| 画面 | React(JavaScript)+ Vite | Nuxt 4(Vue 3, TypeScript)。静的に書き出して S3 + CloudFront で配信 |
| API | Java + Spring Boot(EC2 + Docker) | API Gateway(HTTP API)+ Lambda(Node.js, TypeScript, Hono) |
| データベース | PostgreSQL + Flyway | DynamoDB |
| ログイン | 自作 + Spring Security | Amazon Cognito |
| リアルタイム | Server-Sent Events | API Gateway WebSocket API |
| AWS の構築 | 手作業のスクリプト | AWS CDK(TypeScript) |
| テスト | JUnit / Vitest / 自作 E2E | Vitest / Playwright |

- サーバーを持たない構成にして、**ほぼ無料で常に公開しておける**ようにする(前回はサーバーを普段止めていた)。
- 見やすさの方針(大きい文字・高コントラスト・色だけに頼らない・キーボード操作・スマートフォン対応)は引き継ぐ。

## 利用者像
| 利用者 | できること |
|---|---|
| 閲覧者(ログインなし) | 公開リンクのしおりを読み取り専用で見る(地図・経路を含む)、会員登録・ログイン |
| 会員 | 旅の作成、招待リンクからの参加、自分の旅の一覧 |
| 旅のメンバー | その旅のしおりの編集・投票・割り勘・コメント |
| 旅のオーナー | メンバーのできること + 旅の情報の変更・削除、招待リンクと公開リンクの発行・停止、メンバーを外す |

## 機能要件(初版の範囲)

### 1. 会員
1. 会員登録(メールアドレス・パスワード・表示名。確認コードをメールで送る)
2. ログイン・ログアウト
3. パスワードの再設定
4. 表示名の変更

### 2. 旅
1. 旅の作成(タイトル・開始日・終了日・行き先)。作った人がオーナーになる
2. 自分が参加している旅の一覧
3. 招待リンクの発行 → リンクを開いた会員がメンバーとして参加する
4. オーナーによる旅の情報の変更・削除、メンバーを外す
5. メンバーが自分から抜ける
6. 1 つの旅のメンバーは **50 人まで**(オーナーを含む)。上限に達した招待リンクでは参加できない
7. オーナーが抜ける・退会するときは、**別のメンバーにオーナーを引き継ぐ**(オーナーが選ぶ。選ばずに退会した場合は、いちばん早く参加したメンバーに自動で引き継ぐ)
8. メンバーが 1 人だけの旅でも、その人の退会で**旅は削除しない**。旅は残り、公開リンクがあれば引き続き見られる。作者名は「退会した会員」と表示する

### 3. しおり(旅程)
1. 日ごとの予定の追加・編集・削除(時刻・タイトル・場所・メモ)
2. 予定の並べ替え(同じ日の中、別の日への移動)
3. **同時編集**: 予定 1 件を単位にした楽観ロック。他の人が先に変えていたら、両方の内容を見せて選ばせる
4. 編集中の予定に「○○さんが編集中」と表示する

### 4. 地図・経路(Google マップ)
1. 予定の場所を地名で検索して登録する(入力中に候補が出る)
2. 旅の画面に、目的地周辺の地図と予定の場所のピンを表示する
3. 1 日の予定を時刻順に結んだ経路と、区間ごとの移動時間を表示する(車・徒歩・公共交通を切り替え)
4. 各予定から Google マップを開ける
5. 予定が並べ替えられたら、全員の地図の経路も更新される

### 5. 行きたい場所の投票
1. 候補の追加(場所・ひとこと)
2. 投票・取り消し(1 人 1 票/候補)
3. 候補を採用して旅程に入れる

### 6. 割り勘
1. 支出の記録(内容・金額・払った人・対象のメンバー)
2. 通貨は**円だけ**(1 円単位。割り切れない端数は、払った人の負担に寄せる)
3. 精算額の自動計算(誰が誰にいくら払えばよいか。送金の回数が少なくなるように)

### 7. コメント
1. 予定ごとのコメントの投稿・削除(自分のものだけ)

### 8. リアルタイム
1. 旅程・投票・割り勘・コメントの変更が、再読み込みなしで全員の画面に届く
2. その旅を今見ているメンバーを表示する

### 9. 公開しおり
1. オーナーが読み取り専用の公開リンクを発行・停止できる
2. 公開リンクではログインなしで旅程・地図・経路と、**メンバーの表示名**を見られる(割り勘・コメントは見せない)

## 第 2 版以降
旅の後の写真記録(S3)、持ち物チェックリスト、通知、Google ログイン、オフライン対応。

## 非機能要件
- **安全**: すべての API で、ログイン・その旅のメンバーか・オーナーかをサーバー側で確かめる。Google マップの API キーはリファラーと API の種類で制限し、git に入れない
- **費用**: AWS は使った分だけの料金になる構成にする。Google マップは各 API の毎月の無料枠に収まるよう、1 日の利用上限を設定する
- **性能**: 旅 1 件の画面は、DynamoDB への問い合わせ 1 回で表示に必要なデータを取れるように設計する
- **見やすさ**: WCAG 2.2 AA を目安。地図に頼らず、予定の一覧だけでも旅程がわかるようにする
- **テスト**: API の単体テスト、DynamoDB Local での結合テスト、Playwright で 2 つのブラウザを使った同時編集の確認。GitHub Actions で毎回流す

## 決定事項のまとめ
| 項目 | 決定 |
|---|---|
| アプリの名前 | トリトリ(TriTri) |
| 1 つの旅のメンバーの上限 | 50 人 |
| 割り勘の通貨 | 円だけ |
| 公開リンクでのメンバーの表示名 | 見せる |
| オーナーが退会したとき | 別のメンバーが引き継ぐ。メンバーが 1 人だけでも旅は削除しない |
