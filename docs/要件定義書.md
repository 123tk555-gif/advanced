# Tri-Tri 要件定義書

> 状態: 確認事項はすべて決定済み(最後の「決定事項のまとめ」を参照)。

## 概要
**Tri-Tri**(トリトリ)は、友人や家族と、**1つの旅のしおりを全員で同時に作る** Web アプリ。旅程の編集・行きたい場所の投票・割り勘・コメントを、メンバー同士がリアルタイムにやり取りする。予定の場所は Google マップで地図と経路を表示する。
最終的にインターネット上へ公開する。

## 背景・方針
- 講義の課題「複数のユーザーが情報を双方向にやり取りし、共有する Web アプリ」として作る。
- 前回の SNS アプリ(Leafline)から、**TypeScript と AWS 以外の技術をすべて入れ替える**(課題の指示)。

| 層 | 前回(Leafline) | 今回 |
|---|---|---|
| 画面 | React(JavaScript)+ Vite | Nuxt 4(Vue 3, TypeScript)。静的に書き出して S3 + CloudFront で配信 |
| API | Java + Spring Boot(EC2 + Docker) | API Gateway(HTTP API)+ Lambda(Node.js, TypeScript, Hono) |
| データベース | PostgreSQL + Flyway | DynamoDB |
| ログイン | 自作 + Spring Security | Amazon Cognito |
| リアルタイム | Server-Sent Events | API Gateway WebSocket API |
| AWS の構築 | 手作業のスクリプト | AWS CDK(TypeScript) |
| テスト | JUnit / Vitest / 自作 E2E | Vitest / Playwright |

- サーバーを持たない構成にして、**ほぼ無料で常に公開しておける**ようにする(前回はサーバーを普段止めていた)。
- 見やすさの方針(読みやすい文字・高コントラスト・色だけに頼らない・キーボード操作・スマートフォン対応)は引き継ぐ。
- 見た目: 配色は**青を基調**にする(ヘッダーは濃い青、背景は淡い青、カードは白)。文字は 16px を基準にし、枠線は細め(1px)。ライト・ダークとも、文字と背景のコントラスト比は 4.5 以上にする。

## 利用者像
| 利用者 | できること |
|---|---|
| 閲覧者(ログインなし) | 公開リンクのしおりを読み取り専用で見る(地図・経路を含む)、会員登録・ログイン |
| 会員 | 旅の作成、招待リンクからの参加申請、自分の旅の一覧 |
| 旅のメンバー | その旅のしおりの編集・投票・割り勘・コメント、招待リンクのコピー |
| 旅のオーナー | メンバーのできること + 参加申請の承認・却下、旅の情報の変更・削除、招待リンクと公開リンクの発行・停止、メンバーを外す |

## 機能要件(初版の範囲)

### 1. 会員
1. 会員登録(メールアドレス・パスワード・表示名。確認コードをメールで送る)
2. ログイン・ログアウト
3. パスワードの再設定
4. 表示名の登録・変更(20 文字まで)。旅を作る・参加する前に登録が必要。変更すると、参加中の旅のメンバー一覧・コメントの名前にも反映される
5. 退会: 参加していた旅での名前は「退会した会員」になり、支出・コメントなどの記録は残る。オーナーの旅は引き継ぐ(下の「旅」の 8・9)。未処理の参加申請は消える

### 2. 旅
1. 旅の作成(タイトル 50 文字まで・開始日・終了日・行き先 50 文字まで(省略可))。作った人がオーナーになる。旅の日数は **30 日まで**(日ごとの予定の画面が使いにくくならないように)
2. 自分が参加している旅の一覧。申請中(承認待ち)の旅は、タイトルだけを別に表示する
3. 招待リンク: 旅を作ると発行される。**有効期限は 7 日**。メンバー全員が見てコピーできる。発行し直し(新しい期限)・停止はオーナーだけ。発行し直すと古いリンクはすぐ使えなくなる
4. **参加は承認制**: 招待リンクを開いた会員は「参加申請」をする。**オーナーが承認して初めてメンバーになり、しおりが見られる**。オーナーは却下もできる。未処理の申請は 1 つの旅につき 50 件まで
   - 招待リンクの画面で見せるのは、旅のタイトル・メンバー数・自分の申請の状態だけ
   - 期限切れ・停止・発行し直す前のリンクは、存在しないリンクと同じ「見つかりません」
5. オーナーによる旅の情報の変更・削除、メンバーを外す。旅の情報の変更では、予定がある日より短くはできない
6. メンバーが自分から抜ける
   - 外された・抜けた人の支出・投票・コメントは残す(精算が合わなくならないように)。コメントの名前は「元メンバー」と表示する
   - 外された人も、招待リンクから申請し直して承認されれば戻れる
7. 1 つの旅のメンバーは **50 人まで**(オーナーを含む)。上限に達した招待リンクでは参加できない
8. オーナーが抜ける・退会するときは、**別のメンバーにオーナーを引き継ぐ**(オーナーが選ぶ。選ばずに退会した場合は、いちばん早く参加したメンバーに自動で引き継ぐ)
9. メンバーが 1 人だけの旅でも、その人の退会で**旅は削除しない**。旅は残り、公開リンクがあれば引き続き見られる。作者名は「退会した会員」と表示する

### 3. しおり(旅程)
1. 日ごとの予定の追加・編集・削除(時刻・タイトル 100 文字まで・場所・メモ 1000 文字まで)。予定は 1 つの旅に **300 件まで**
2. 予定の並べ替え(同じ日の中、別の日への移動)
3. **同時編集**: 予定 1 件を単位にした楽観ロック。他の人が先に変えていたら、両方の内容を見せて選ばせる
4. 編集中の予定に「○○さんが編集中」と表示する

### 4. 地図・経路(Google マップ)
1. 予定の場所を地名で検索して登録する(入力中に候補が出る)。保存するのは **Google の場所の ID と、利用者が入力した表示名(200 文字まで)だけ**。座標と Google の名前は保存しない(Google の規約)。座標は表示のたびに ID から取る
2. 旅の画面に、目的地周辺の地図と予定の場所のピンを表示する
3. 1 日の予定を時刻順に結んだ経路と、区間ごとの移動時間を表示する(車・徒歩・公共交通を切り替え)。経路が見つからない区間は、目安の時間を出さずに「Google マップで調べる」リンクを出す。**日本の公共交通は Google の API が経路を返さないため、いつもリンクになる**
4. 各予定から Google マップを開ける
5. 予定が並べ替えられたら、全員の地図の経路も更新される

### 5. 行きたい場所の投票
1. 候補の追加(名前 100 文字まで・場所・ひとこと 100 文字まで)。1 つの旅に **100 件まで**。消せるのは出した本人とオーナー
2. 投票・取り消し(1 人 1 票/候補)。誰が投票したかも見える
3. 候補を採用して旅程に入れる(候補の名前・場所・ひとことで予定を作る)。同じ候補は 1 回だけ採用できる

### 6. 割り勘
1. 支出の記録(内容 50 文字まで・金額 1000 万円まで・払った人・対象のメンバー)。払った人・対象は今のメンバーだけ。1 つの旅に **500 件まで**。削除はメンバーなら誰でも
2. 通貨は**円だけ**(1 円単位。割り切れない端数は、払った人の負担に寄せる)
3. 精算額の自動計算(誰が誰にいくら払えばよいか。送金の回数が少なくなるように)

### 7. コメント
1. 予定ごとのコメントの投稿(200 文字まで)・削除(自分のものだけ)。1 つの予定に **200 件まで**。予定を消すと、その予定のコメントも消える

### 8. リアルタイム
1. 旅程・投票・割り勘・コメントの変更が、再読み込みなしで全員の画面に届く
2. その旅を今見ているメンバーを表示する

### 9. 公開しおり
1. オーナーが読み取り専用の公開リンクを発行・停止できる
2. 公開リンクではログインなしで旅程・地図・経路と、**メンバーの表示名**を見られる(割り勘・コメントは見せない)

## 非機能要件
- **安全**: すべての API で、ログイン・その旅のメンバーか・オーナーかをサーバー側で確かめる。確かめ忘れを防ぐため、確認は共通の仕組み(ミドルウェア)で行い、**全 API を自動で列挙して「未ログインは 401・メンバー以外は 404」をテストする**。メンバー以外には、旅があることも知られないようにする(旅が無いときと同じ応答)。応答には必要な項目だけを入れる。Google マップの API キーはリファラーと API の種類で制限し、git に入れない
- **費用**: AWS は使った分だけの料金になる構成にする。Google マップは各 API の毎月の無料枠に収まるよう、1 日の利用上限を設定する
- **性能**: 旅 1 件の画面は、DynamoDB への問い合わせ 1 回で表示に必要なデータを取れるように設計する
- **見やすさ**: WCAG 2.2 AA を目安。地図に頼らず、予定の一覧だけでも旅程がわかるようにする
- **テスト**: API の単体テスト、DynamoDB Local での結合テスト、Playwright で 2 つのブラウザを使った同時編集の確認。GitHub Actions で毎回流す

## 決定事項のまとめ
| 項目 | 決定 |
|---|---|
| アプリの名前 | **Tri-Tri**(読み方: トリトリ)。ロゴは「Tri-Tri」の文字を太いゴシック体で青く塗り、白い太めの線で縁取る |
| 1 つの旅のメンバーの上限 | 50 人 |
| 割り勘の通貨 | 円だけ |
| 公開リンクでのメンバーの表示名 | 見せる |
| 場所の保存(2026-11-22) | Google の場所の ID と、利用者が入力した表示名だけ。座標は表示のたびに取る |
| 日本の公共交通の移動時間(2026-11-22) | 出さない。Google マップで調べるリンクにする |
| オーナーが退会したとき | 別のメンバーが引き継ぐ。メンバーが 1 人だけでも旅は削除しない |
